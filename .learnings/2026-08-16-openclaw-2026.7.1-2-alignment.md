## 3. 🟡 唯一发现的对齐问题：compaction 字节守卫被废

### 3.1 现场

```json
"compaction": {
  "mode": "safeguard",
  "memoryFlush": { "model": "siliconflow/Qwen/Qwen3-8B" },
  "truncateAfterCompaction": false,    ← 关键
  "maxActiveTranscriptBytes": "1mb",  ← byte guard
  "notifyUser": true
}
```

### 3.2 官方明确警告（`docs/concepts/compaction.md` L88-92）

> The byte guard requires `truncateAfterCompaction: true`. Without transcript rotation, the active file would not shrink and the guard remains inactive.

### 3.3 影响

- 现状：`maxActiveTranscriptBytes: "1mb"` 启用了字节守卫，但 `truncateAfterCompaction: false` 让守卫**完全无效**——本地 JSONL 不会轮转。
- 风险：长 session 的本地 JSONL 会无限增长（虽然模型 context 由 provider 端管）。
- 这不是"bug"，是"配置意图被掩盖"——`truncateAfterCompaction: false` 是想"保留整段历史方便回看"；但既然设了 `1mb` 守卫，又没启用轮转，两者意图冲突。

### 3.4 修复方案（请用户二选一）

| 方案 | 改动 | 含义 |
|---|---|---|
| **A. 让守卫真正生效** | `truncateAfterCompaction: true` | 每次 compaction 后**会旋转**到新 transcript 文件，老历史保留在归档里；`maxActiveTranscriptBytes: "1mb"` 真的开始控制活跃文件大小 |
| **B. 承认我们不想要轮转** | 删 `maxActiveTranscriptBytes: "1mb"` | 让"完整 JSONL 历史"和"无主动轮转"保持一致；guard 失效的现状改为"我们根本没想要 guard" |
| **C. 维持现状不动** | 不动 | 用户明知取舍，接受 guard 无效 |

**推荐 A**：与 OpenClaw 默认行为一致，避免长 session 文件无限增长。改后需要 `gateway restart` 生效。

## 7. 自我更新：本会话值得记的 3 件事

### 7.1 OpenClaw 2026.7.1-2 是 plugin metadata fix（#108336）

不是新功能 patch。Plugin 自然滚到 -2 还需各自 patch 发布。

### 7.2 OpenClaw docs 是 npm 包的同步组成部分

`~/.nvm/versions/node/v24.15.0/lib/node_modules/openclaw/docs/` 的 mtime 与 npm 安装时间一致，且与 `https://docs.openclaw.ai` 同源（同一 docs 仓库）。所以本地 docs **就是**当前 npm 版本的官方文档——**不需要每次去 GitHub 拉**。

### 7.3 plugin 版本矩阵：主包 patch / plugin patch 解耦

`openclaw 2026.7.1-2` 主包已升 patch 2，但所有 stock + tracked plugins 还停在 `2026.7.1`（patch 0）。这是 OpenClaw 的设计：plugin 走独立 npm dist-tag，#108336 修复让它们能"装得上 patch 2"，但**主动跑到 patch 2**还得等 plugin 自己发 patch 版。
